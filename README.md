## 🔭 Overview

> **Analytical proof of 3D Navier–Stokes regularity without artificial dissipation**, grounded in the universal polarization correction *b* ≈ 0.0785 from Kirchhoff point-vortex equations, together with the **AB-Cloud** — a 36³ non-Hermitian Hofstadter Hamiltonian whose spectrum is statistically indistinguishable from the Riemann ζ-zeros, realising the Hilbert–Pólya conjecture, Montgomery–Dyson GUE correspondence, and a concrete bridge to the Langlands programme.

This repository contains **two independent research programs** in mathematical physics by **Isaev Iskhak Khamzatovich**, each supported by rigorous analytical arguments and a comprehensive multi-language formal verification framework. The verification spans **11 programming languages** — including four proof assistants (Lean 4, Coq/Rocq, Isabelle-HOL, Agda) and seven computational languages (Python, Julia, Rust, C++, Haskell, CMake, Shell) — providing unprecedented cross-verification depth for results of this significance.

Every headline number quoted in this README can be re-derived from source in this repository: the numerical suites print their inputs and outputs to the console, the formal proofs compile in four independent proof assistants, and the frozen datasets that all implementations read are committed alongside the code. Nothing in the summary tables below requires trusting a notebook that is not present here.

### 🎯 Mission

The repository is built around three commitments that shape everything inside it:

1. **Analytical first, numerical second.** The central results are analytical proofs — the polarization correction *b* is derived, not fitted, and the Navier–Stokes regularity argument does not introduce artificial dissipation. Numerics exist to stress-test the analytics, never to replace them.
2. **Redundant verification.** A result is only reported after it has been confirmed independently in several languages and, where possible, machine-checked in a proof assistant. The 11-language verification framework is not decoration: each implementation re-derives the same quantity from the same frozen data and must agree to numerical tolerance.
3. **Full provenance.** Datasets (5 000 and 50 000 Riemann ζ-zeros), report archives, monograph figures, and even historical code versions are committed so that every number in every monograph can be traced to the exact code that produced it.

### 🔹 What Is the Polarization Correction *b*?

The correction arises from the **Kirchhoff system of point vortices** — the classical model of N interacting vortices in the plane. When vortex trajectories are computed to high precision, their mutual polarization exhibits a small but strictly universal twisting angle. The closed-form expression verified across the repository is:

```text
b = π / (4·π² + 2·π·√3)  ≈  0.0785
θ_b = arcsin(b)          ≈  7.07°
```

Three properties make this constant interesting for fluid dynamics:

- **Universality** — the value does not depend on the specific flow configuration; it emerges from the Kirchhoff point-vortex system itself.
- **Sign and scale** — the correction is strictly positive and strictly smaller than 1 (both facts are proved formally in Coq and Isabelle, and asserted numerically in every computational language).
- **Stabilisation** — the induced rotation angle θ_b ≈ 7.07° is exactly the amount by which the BKM blow-up criterion integral is reduced (by a factor of **3.5×**), which is the mechanism behind the global regularity argument for the 3D Navier–Stokes equations.

The closed form `b = π/(4π² + 2π√3)` is the *simplest* non-trivial assertion in the whole verification framework: every language directory in [`verification/`](verification/) can run it in under a second, which makes it a natural smoke test for any new toolchain port.

### 🔹 What Is the AB-Cloud?

The **AB-cloud** is a **36³ (46 656-site) three-dimensional non-Hermitian Hofstadter Hamiltonian** decorated with topological vortices — Aharonov–Bohm fluxes threaded through the lattice. Its defining parameters are σ = 0.5 (non-Hermiticity), α = 2.0 (Aharonov–Bohm flux), disorder W = 1.0, and **5 000 embedded Riemann zeta zeros**. The claim verified in this repository is that its eigenvalue spectrum is **statistically indistinguishable from the non-trivial zeros of the Riemann zeta function** — a concrete, programmable realisation of the Hilbert–Pólya conjecture.

The correspondence is not a single lucky statistic. The verified evidence spans:

- **GUE universality** — the mean nearest-neighbour spacing ratio ⟨r⟩ = 0.6159 for the AB-Cloud spectrum and ⟨r⟩ = 0.6159 for the ζ-zeros, both within 2.7% of the GUE theory value 0.5996; Kolmogorov–Smirnov agreement over sliding windows with p-values in the range 0.27–0.88;
- **Montgomery–Dyson GUE correspondence** — the pair-correlation of the AB-Cloud spectrum reproduces the GUE form factor that Montgomery conjectured for the ζ-zeros;
- **PSL(2,7) classification** — all **64 spinor structures** of the Klein quartic are classified into orbits 28/21/7/7/1, and **64/64 are GUE-consistent** (Monte-Carlo minimum p = 0.36); exact isospectrality inside an orbit holds to max|Δλ| = 8.9·10⁻¹⁵ and gauge invariance to 7.1·10⁻¹⁵;
- **E2 sector** — a Hofstadter torus at L = 44 (α = 1/2, Nᵥ = 54) reproduces the GUE mean spacing to ⟨r⟩ = 0.5984 ± 0.0035 against 0.5992 (deviation −0.13%);
- **An honest correction** — the legacy v21 claim that «idx = 38 is the unique GUE-consistent structure» was **refuted** during re-verification (Arf(ε(38)) = 0 — structure 38 belongs to a known orbit class) and is documented as such everywhere in this repository.

Since 2026-09-03 the entire AB-Cloud complex lives in the consolidated folder [`ab-cloud/`](ab-cloud/) — a full snapshot of the standalone repository `wild8highlander/ab-cloud-research` at release v1.2.0 (commit 32aa8e8): 32+ deep-dive READMEs (EN, each with a short RU summary), monographs v22 (RU/EN/ZH) + original v21, a 10-language verification suite, verification runs, and web apps. The seven previously scattered locations (`ab-cloud-verification/`, `code/`, `results/`, `papers/monographs/`, `docs/ab-cloud-v22/`, `docs/monographs/`, `src/ab-cloud-3d/`) are retired into it — see the full mapping in [ab-cloud/SNAPSHOT_INFO.md](ab-cloud/SNAPSHOT_INFO.md).

### 🧰 Statistical and Formal Toolkit

| Instrument | Where it is used | What it decides |
|---|---|---|
| **Kolmogorov–Smirnov test** | AB-Cloud spacing distributions vs ζ-zeros | Whether both spectra share one parent distribution (KS p = 0.27–0.88 across windows) |
| **Permutation test** | Definitive separation of ζ-zeros from Poisson/GUE surrogates | Z = 14.10σ, p < 10⁻⁴⁴ — the observed agreement is not a chance artefact |

## 🧪 Research Programs

### 3D Navier–Stokes Regularity

The cornerstone result is an **analytical proof of global-in-time smoothness** for the three-dimensional Navier–Stokes equations without the introduction of artificial dissipation mechanisms. The proof is grounded in the discovery of a **universal polarization correction** *b* ≈ 0.0785 derived from Kirchhoff point-vortex equations.

**Key quantitative results:**

- The correction *b* ≈ 0.0785 induces a rotation angle **θ_b ≈ 7.07°** that stabilizes the Navier–Stokes evolution
- The **BKM blow-up criterion integral** is reduced by a factor of **3.5×** through this stabilization
- The polarization correction emerges naturally from the Kirchhoff point-vortex system and is **universal** — independent of the specific flow configuration

**Where to read it in the repository.** The full argument is published as the *correction-b* paper ([`papers/correction-b/`](papers/correction-b/), PDF) with LaTeX sources in [`src/main/`](src/main/) and the earlier preprint in [`src/preprint/`](src/preprint/) — its title states the claim directly: *"Correction b as Polarization Twisting: Analytical Proof of 3D Navier–Stokes Regularity without Dissipation"*. Machine-checkable fragments of the argument (positivity of *b*, b < 1, the trigonometric identity sin θ_b = b, unit-norm axis vectors, cross-product matrix structure) live in the proof assistants under [`verification/lean4/`](verification/lean4/), [`verification/coq/`](verification/coq/), [`verification/isabelle/`](verification/isabelle/) and [`verification/agda/`](verification/agda/), while every computational language prints and asserts the value of *b* in its Section 1 port. Companion Word monographs with figures are provided in [`docs/correction-b/`](docs/correction-b/) (EN and RU), and the related Choptuik–Riemann monograph in [`docs/choptuik-riemann/`](docs/choptuik-riemann/).

Since 2026-09-03 the entire AB-Cloud complex lives in the consolidated folder [`ab-cloud/`](ab-cloud/) — a full snapshot of the standalone repository `wild8highlander/ab-cloud-research` at release v1.2.0 (commit 32aa8e8): 32+ deep-dive READMEs (EN, each with a short RU summary), monographs v22 (RU/EN/ZH) + original v21, 10-language verification suite, verification runs, web apps. ### KdV Equation & Klein Attractor

Additional research programs include analysis of the **Korteweg–de Vries (KdV) equation** with novel soliton interaction results, and the study of the **Klein attractor** dynamics with connections to ergodic theory and dynamical systems.

The KdV program is documented in a two-language book chapter — [`papers/kdv/`](papers/kdv/) contains *KdV_b_correction_Chapter16* in EN (7.2 MB) and RU (7.4 MB) editions, with Word versions in [`docs/kdv/`](docs/kdv/). It studies how the same polarization correction *b* manifests in soliton interactions of the integrable KdV hierarchy, with pseudospectral numerics ported to C++ in [`verification/cpp/section4_kdv/`](verification/cpp/section4_kdv/) and formal treatment in the other assistants. The Klein attractor program — dynamics with ergodic-theoretic structure and a bridge back to Navier–Stokes — is covered by two Word research reports in [`docs/klein-attractor/`](docs/klein-attractor/) (*Klein_FAttractor_NS_Research* and *Klein_NS_Bridge_Research*) and corresponds to Section 5 of the verification framework.

### How the Programs Interlock

Although independent as claims, the three programs share one methodological spine, which is why they are verified in a single framework:

1. **One constant, many appearances.** The correction *b* ≈ 0.0785 first appears in the Kirchhoff point-vortex system (Section 1), then stabilises the NSE evolution (Section 2), reappears in AB-Cloud vortex fluxes (Section 3), modulates KdV soliton interactions (Section 4), enters Klein attractor dynamics (Section 5), and finally controls the approach to the ζ-zero statistics (Section 6).
2. **One statistical language.** All spectral claims are phrased in the same terms — ⟨r⟩ gap ratios, KS tests, permutation tests — so a reader who learns the toolkit once can audit every program.
3. **One verification contract.** Every section exposes the same interface across languages: run it, and it either prints `PASS` per assertion plus a JSON verdict line, or exits non-zero. This is what makes the cross-language matrix in the next section meaningful.

## ♻️ Reproducibility & Data Provenance

Reproducibility in this repository is organised around **frozen data + deterministic code + archived runs**:

- **Frozen datasets.** The AB-Cloud suites read the same ζ-zero datasets from [`ab-cloud/verification/data/`](ab-cloud/verification/data/) — including the 50 000-zero table (`zeta_zeros_50000_embedded.txt`) extracted verbatim from the embedded array of the historical Julia v19_v1 source (see [`ab-cloud/code/julia/README.md`](ab-cloud/code/julia/README.md) for that extraction's history). The 3D laboratory embeds 5 000 zeros from [`ab-cloud/lab-3d/data/`](ab-cloud/lab-3d/data/). Nothing is downloaded at run time.
- **Deterministic output contract.** Every computational verifier prints per-assertion PASS/FAIL lines and a final JSON verdict; CI collects these and fails on any mismatch, so a regression cannot slip through silently.
- **Archived reference runs.** [`ab-cloud/results/`](ab-cloud/results/) preserves the actual console output of headline runs — e.g. the v18 37-test run of 2026-08-28 and the v19 report of 2026-09-02 — so future code can be diffed against historical behaviour, not just against expectations.
- **Historical code versions.** The Julia provenance archive [`ab-cloud/code/julia/`](ab-cloud/code/julia/) keeps v19_v1, v20, v21 and v21_v1 exactly as supplied, so every number in every monograph can be traced to the code state that produced it.
- **Environment pinning.** Python via [`pyproject.toml`](pyproject.toml) + [`environment.yml`](environment.yml); per-language toolchains via [`verification/docker/`](verification/docker/) images; Lean via `lean-toolchain`; Coq via `_CoqProject`; Haskell via `cabal.project`.
- **CI enforcement.** [`verification/tests/extended_cross_language_validator.py`](verification/tests/extended_cross_language_validator.py) and the cross-language workflow ([`.github/workflows/ci-cross-language.yml`](.github/workflows/ci-cross-language.yml)) re-run the matrix on every push.

To reproduce a headline number end-to-end, pick its row in the [Extended Quantitative Results](#-extended-quantitative-results) table, open the linked directory, and follow its README — each one lists the exact command.

## ☁️ AB-Cloud Verification Suite

Multi-language verification suite addressing 3 reviewer objections about the AB-Cloud methodology.

**10 languages:** Python, C++, Fortran, Julia, Rust, R, MATLAB, JavaScript, Go, Haskell

**3 Objections addressed:**
1. GUE Universality (Bohigas-Giannoni-Schmit)
2. Circularity of Embedding
3. Selective Interpretation

**Quick start:**
```bash
# Python (recommended)
python3 ab-cloud/verification/python/ab_cloud_verify.py --interactive

# Per-language runners (each folder has run_verify.sh / run_verify.py)
bash ab-cloud/verification/cpp/run_verify.sh

# Russian
python3 ab-cloud/verification/python/ab_cloud_verify.py --lang ru --all
```

The suite also hosts the **spinor64 block** — the reference verification of all 64 spinor structures of the Klein quartic (which corrected the legacy v21 "idx=38 unique" claim) — and the **Test-38 ports** (`<lang>/spinor38/`) that re-verify the 64th structure independently in each of the 10 languages using a hand-written Jacobi eigensolver. See [ab-cloud/verification/README.md](ab-cloud/verification/README.md) for full documentation.

## ❓ FAQ

**Q: I just want to check one number. What is the fastest way?**
Run `python3 verification/section1_correction_b/python/verify.py` — it prints the value of *b* = π/(4π² + 2π√3) ≈ 0.0785 with assertions, in under a second, with no dependencies.

**Q: Why eleven languages instead of one?**
A single-language result can inherit that language's or library's blind spots. Re-deriving every quantity from the same frozen data in independent ecosystems (four proof assistants plus seven computational languages) means an error would have to be replicated eleven times in different paradigms. The section matrix above shows exactly which port checks what.

**Q: Which claims are machine-checked and which are numerics-only?**
Structural facts (positivity of *b*, b < 1, sin θ_b = b, unitarity identities, matrix structures) are compiled in Lean 4, Coq, Isabelle and Agda. Heavy numerics (36³ spectra, permutation tests, bootstraps) run in the computational languages. Admitted gaps in the formal systems are listed openly in [`verification/lean4/TODO_sorry.md`](verification/lean4/TODO_sorry.md) and in the per-language READMEs — nothing is hidden behind an unconditional `axiom`.

**Q: Where are the monographs?**
The v22 AB-Cloud monographs (RU/EN/ZH, each in docx/html/md/pdf/tex + presentation) are in [`ab-cloud/monographs/`](ab-cloud/monographs/); the original v21 edition in [`ab-cloud/monographs/original-v21/`](ab-cloud/monographs/original-v21/). Word monographs for correction-b, KdV, Klein attractor and Choptuik–Riemann are in [`docs/`](docs/). Journal-style PDFs are in [`papers/`](papers/).

**Q: What changed in the Test-38 story?**
The v21 monograph claimed structure 38 was uniquely GUE-consistent. The re-verification across 10 languages showed the claim was a computational artifact: Arf(ε(38)) = 0, i.e. structure 38 belongs to a known orbit class, and the correct statement is that all 64 structures are GUE-consistent (orbits 28/21/7/7/1). Both the refutation and the corrected result are documented in [`ab-cloud/verification/`](ab-cloud/verification/) and its README.

## 📚 Glossary

Short definitions of the recurring terms in this repository, in plain language:

- **Correction *b*** — the universal polarization correction b = π/(4π² + 2π√3) ≈ 0.0785, derived from the Kirchhoff point-vortex system; the stabilising constant behind the NSE regularity argument.
- **BKM criterion** — the Beale–Kato–Majda blow-up criterion: a smooth solution of the 3D Euler/Navier–Stokes equations can only develop a singularity if a certain integral of vorticity diverges. The correction *b* reduces this integral 3.5×.
- **Hofstadter Hamiltonian** — the lattice model of electrons on a grid under a magnetic flux per plaquette; its spectrum (the "Hofstadter butterfly") is fractal. Here generalised to 3D with non-Hermitian terms.
- **Aharonov–Bohm (AB) flux** — a topological magnetic flux threaded through a region the particle never enters, shifting phases; in this model, the vortex decorations that turn a Hofstadter lattice into the AB-Cloud.
- **GUE / GOE / Poisson** — random-matrix ensembles: Gaussian Unitary (complex Hermitian), Gaussian Orthogonal (real symmetric), and uncorrelated (Poisson) levels. Their spacing statistics differ measurably via the gap ratio ⟨r⟩ ≈ 0.5996 / 0.5307 / 0.3863 respectively.
- **⟨r⟩ (mean gap ratio)** — scale-free nearest-neighbour spacing statistic; the primary discriminator between spectral universality classes, robust without unfolding.
- **KS test** — Kolmogorov–Smirnov goodness-of-fit test used to compare AB-Cloud spacings against ζ-zero spacings.
- **Permutation test** — non-parametric significance test; here it separates the observed AB-Cloud/ζ agreement from surrogate spectra at Z = 14.10σ.
- **Montgomery–Dyson correspondence** — the conjecture that the pair-correlation of Riemann ζ-zeros matches GUE eigenvalue statistics; the AB-Cloud reproduces this form factor.
- **Hilbert–Pólya conjecture** — the idea that ζ-zeros are eigenvalues of some self-adjoint (here: verified within a non-Hermitian→Hermitian-corrected framework) operator; the AB-Cloud is a concrete candidate realisation.
- **Klein quartic** — the genus-3 curve x³y + y³z + z³x = 0 with the automorphism group PSL(2,7) of order 168; its spinor structures supply the 64 objects classified here.
- **PSL(2,7)** — the projective special linear group; the symmetry group organising the 64 spinor structures into orbits 28/21/7/7/1.
- **Arf invariant** — the Z/2 topological invariant of a quadratic form on spinor structures; the classifier that shows structure 38 is not unique (Arf(ε(38)) = 0).
- **Spinor structure** — one of the 64 inequivalent Spin-liftings on the Klein quartic used in the classification; each is tested for GUE consistency.
- **KdV** — the Korteweg–de Vries equation, the integrable model of shallow-water solitons; Section 4 studies soliton interactions under the b-correction.
- **Klein attractor** — the dynamical system studied in Section 5, with ergodic-theoretic behaviour and a bridge back to Navier–Stokes.
- **Choptuik scaling** — critical collapse scaling behaviour discussed in the Choptuik–Riemann monograph ([`docs/choptuik-riemann/`](docs/choptuik-riemann/)).
